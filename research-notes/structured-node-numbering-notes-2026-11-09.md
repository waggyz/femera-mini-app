# Notes on structured grid notde numbering

**Current implementation**

- For P1, vert_conn sequence: {0,1}, {1,2}, {2,3},...
- For P2, vert_conn sequence: {0,2}, {2,4}, {4,6},...
- For P3, vert_conn sequence: {0,3}, {3,6}, {6,9},...

Node conn will be:

- For P1, node conn sequence: {0,1}, {1,2}, {2,3},...
- For P2, node conn sequence: {0,2,1}, {2,4,3}, {4,6,5},...
- For P3, node conn sequence: {0,3,1,2}, {3,6,4,5}, {6,9,7,8},...

*NOTE* this numbering scheme results in slightly more compact elem clusters,
though location swapping is needed for out of order access.
Node to coordinate mapping is ordered. Overall, this numbering is likely to perform better.

**Consider the following.**

- For P1, vert_conn sequence: {0,1}, {1,2}, {2,3},...
- For P2, vert_conn sequence: {0,1}, {1,3}, {3,5},...
- For P3, vert_conn sequence: {0,1}, {1,4}, {4,7}, {7,10},...

Node conn will be:

- For P1, node conn sequence: {0,1}, {1,2}, {2,3},...
- For P2, node conn sequence: {0,1,2}, {1,3,4}, {3,5,6},...
- For P3, node conn sequence: {0,1,2,3}, {1,4,5,6}, {4,7,8,9}, {7,10,11,12},...

*NOTE* the second numbering scheme causes elem node 0 index to lag the others,
but element access remains in order, though there is elem 0 special handling.
Node to coordinate mapping is out of order and more complex.
The special handling is likely to compound in higher dimensions
(at element on partition corners, edges, and faces),
so the current implmentation is likely to perform better.
