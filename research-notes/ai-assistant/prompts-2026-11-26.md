 With the aggressive optimization flags in use, the commpiler should be able to inline these with no runtime overhead (perhaps even unrolling the loops).
 
 Perhaps a better alternative is Free<Bars>, i.e., based on the underlying element type directly. An important aspect of Femera performance is limiting each partition to a single element type, all using the same number of intergration points. Also, by limiting edge and face nodes to their natural positions, it simplifed jacobian calculation to needing only the vertex node coordinates (since all the other nodal positions can be computed from those). Further, with this limitation, the simplex elements (Bars, Tris, and Tets) all have constant Jacobians regardless of element order, thus requiring only one Jacobian and determinant for each element. Please compare the, e.g.,  Free<Bars> to Free<Bar1>, alternatives. I think the Free<Bars> architecture might make more sense.
